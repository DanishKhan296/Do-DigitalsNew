## Database model

- **Local development:** SQLite file `db/custom.db` (works out of the box, zero config).
- **Production:** **Turso (libSQL)** — the hosted database. `src/lib/db.ts` switches
  automatically via the official `@prisma/adapter-libsql` driver adapter: when
  `TURSO_DATABASE_URL` + `TURSO_AUTH_TOKEN` are set it talks to Turso, otherwise it uses
  the local SQLite file. The Prisma schema needs **no provider changes**.
- Sync schema + content to Turso: `bun run turso:push`
- Verify the migration: `bun run turso:verify`
- On Vercel, `DATABASE_URL` is **not** required (the adapter connects directly).

## Deliberately NOT included (and why)

- `.env` — contains machine-specific values (including your private Turso token). Use
  `.env.example` and create your own `.env`. See "Secrets" below.
- `node_modules/` — restored with `bun install` (or `npm install`) from `bun.lock`.
- `.next/` — build output, regenerated by `bun run build`.
- `.git/` — repository metadata. History intentionally excluded so no historical secrets
  can leak. Initialize a fresh repo with `git init`.
- `skills/`, `tool-results/`, `download/`, `dev.log` — sandbox/platform artifacts, not part of the website.

## Quick start (local)

```bash
bun install          # or: npm install
cp .env.example .env # then set AUTH_SECRET (see below)
bun run db:push      # sync schema (optional — db/custom.db is already populated)
bun run dev          # http://localhost:3000
```

Default admin (only on a FRESH database): `admin` / `DoDigitals@2025` — change it immediately
in Admin → Account. The shipped `db/custom.db` already contains the real admin account.

## Secrets — how to configure safely

1. Never put real secrets in files you commit or share.
2. Copy `.env.example` to `.env` for local development and fill in:
   - `DATABASE_URL` — local SQLite: `file:../db/custom.db`
   - `TURSO_DATABASE_URL` + `TURSO_AUTH_TOKEN` — from the Turso dashboard → your database → Connect
   - `AUTH_SECRET` — generate with `openssl rand -base64 32`
3. On Vercel: Project → Settings → Environment Variables — add `TURSO_DATABASE_URL`,
   `TURSO_AUTH_TOKEN`, `AUTH_SECRET` (and optionally `ADMIN_PASSWORD`,
   `ADMIN_ALLOWED_ORIGINS`, `APP_URL`). Values live on Vercel's servers, never in the
   repository or in any archive.
4. Full details: `README-DEPLOY.md` (Turso setup, `turso:push`, deployment steps, troubleshooting).
